# Device profile format (`toolkit/devices/<codename>.json`)

Generated by `tools/profile_doc.py` from `tools/profile_spec.py`; the example column is the S10 Lite (r5q).
Addresses and sizes are hex strings. `null` means unknown: `tools/validate_profile.py` lists it under the
stages that need it. Private values (serial, absolute paths) go in `<codename>.local.json` under `local`.

Stages: `safety`, `boot`, `kernel`, `userland`, `display`, `touch`, `battery`, `buttons`, `cpufreq`, `wifi`.


## device

| field | type | needed for | where it comes from | r5q |
|---|---|---|---|---|
| `device.codename` | str | safety | ro.product.device / the kernel DT model (e.g. r5q) | r5q |

| `device.model` | str | safety | adb shell getprop ro.product.model (the runner refuses any other) | SM-G770F |
| `device.name` | str | - | marketing name | Samsung Galaxy S10 Lite |
| `device.soc` | str | boot | SoC part number (sm8150): picks toolkit/socs/<soc>.json | sm8150 |
| `device.soc_name` | str | - | e.g. Snapdragon 855 | Snapdragon 855 (msmnile) |
| `device.android_build` | str | - | ro.build.display.id of the baseline | G770FXXS9HXA1 (Android 13) |

| `device.prefix` | str | boot | file prefix of build products, e.g. r5q (r5q-test68-kernel.bin) | r5q |
