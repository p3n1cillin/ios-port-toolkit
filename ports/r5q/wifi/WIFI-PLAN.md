# Wi-Fi on the Galaxy S10 Lite (r5q) under iOS — plan

## What the hardware is (from `live.dts`)

- **Both PCIe controllers are disabled** (`qcom,pcie@1c00000`, `qcom,pcie@1c08000`: `status = "disabled"`), so the
  `qcom,cnss-qca6390` node is unused. Unlike the S20+ (Broadcom BCM4375 on PCIe, donor `redwood_pcie.c`), there is
  no plug-in radio here.
- The live radio is **`qcom,icnss@18800000`**: the WCN3990-family Wi-Fi block inside the SM8150 (the WCN399x chip
  supplies only the RF). Linux drives it with **ath10k's SNOC bus** (`ath10k_snoc`). The firmware does not run on the
  application processor: it runs on the **modem (MPSS)**, which loads `wlanmdsp.mbn` itself.
  - `membase` 0x18800000 (8 MB): the copy engines (CE) the AP talks to.
  - `smmu_iova_base` 0xa0000000: the window the radio's DMA sees, through apps SMMU stream 0x640 (mask 1).
  - 12 CE interrupts (SPI 0x19e–0x1a9). The iOS kernel has no IRQ path for these yet, so it polls them, as the
    donor's `lx_bus.c` does.
  - MSA memory: 1 MB, fixed region `0xea`. Supplies: vdd-cx-mx, 1.8-xo, 1.3-rfa, 3.3-ch0 (RPMh, owned by the modem/AOP).
- The modem: `qcom,pil-tz-generic`, **PAS id 4**, firmware name `modem` (`modem.mdt` + `.bNN`), memory region
  0x8d800000 + 160 MB. GLINK edge `mpss` over SMEM (0x86000000, 2 MB). APCS IPC doorbell at 0x17c0000c, not IPCC.
  SMP2P with the modem.
- The modem needs two AP-side services before it brings the Wi-Fi firmware up:
  - **rmtfs**: its EFS, the `modemst1`/`modemst2`/`fsg`/`fsc` partitions, through the 2 MB rmtfs shared memory.
  - **TFTP over QRTR**, which it uses to read `wlanmdsp.mbn` and the board data.

## How it maps onto the donor (POCO X5 Pro, WCN6750)

| Stage | Donor (redwood, SM7325) | r5q (SM8150) |
|---|---|---|
| DSP boot | WPSS, TZ PAS 6, `wpss.mdt` | **MPSS, TZ PAS 4, `modem.mdt`** (a bigger image) |
| Doorbells | IPCC | **APCS IPC 0x17c0000c** (bit per edge) |
| Power handshake | AOP QMP mailbox | AOP QMP (SM8150 has it too: `0xc300000`) |
| SMEM / SMP2P / GLINK / QRTR | `redwood_wifi.c` steps 1–14 | same protocols; different item numbers and host id (modem = 1) |
| AP-side services | none needed | **rmtfs + TFTP servers (new)** |
| Firmware handshake | QMI WLFW (`redwood_wlfw.c`) | QMI WLFW (same service, older version: ath10k `qmi.c`) |
| Driver | Linux ath11k on `wifi/lx` (`mk-ath11k.sh`) | **Linux ath10k SNOC on `wifi/lx` (`mk-ath10k.sh`, here)** |
| 802.11 / WPA | `wifi/lx/src/lx_80211.c`, `lx_wpa.c` (mac80211 side) | reused: ath10k is a mac80211 driver too |
| iOS side | `redwood_apple80211.c`, `redwood_sta.c` | reused |

## Stages, each one a test

1. **Driver object** (offline, now): `mk-ath10k.sh`. Compile ath10k core/ce/htc/htt/mac/wmi-tlv/qmi/snoc and the ath
   common library on the layer, then list compile failures and missing names. Next, write the SNOC glue
   (`lx_bus_snoc.c`: a platform device for `qcom,icnss` with its resources, CE register access, polled CE service)
   in place of ath11k's `lx_bus.c`.
2. **Firmware files** (from Android, or from the stock firmware package's `NON-HLOS.bin`): `modem.mdt`/`.bNN`,
   `wlanmdsp.mbn`, `bdwlan.*` board data, and `WCNSS_qcom_cfg.ini` for reference. These go in the small image, as the
   donor's `fw/` does.
3. **Survey (read-only)**: SMEM partitions (`$TOC`), whether the modem's SMP2P item exists, the AOP mailbox, the APCS
   doorbell, and the MSA and modem regions. The donor's steps 1–5 with r5q addresses. Nothing written.
4. **Modem boot**: TZ PAS 4 metadata check, image load, SMP2P item, AOP "image loaded", start, wait for "up".
   Stop it again cleanly at the end of a run, the donor's lesson about restarting a DSP that was not asked to stop.
5. **GLINK + QRTR with the modem**: the donor's steps 12–14 with the `mpss` edge.
6. **rmtfs + TFTP servers**: what the modem asks for, served read-only first (EFS reads; writes kept in RAM rather
   than written back to the phone's partitions).
7. **WLFW handshake** (ath10k `qmi.c`): capabilities, BDF download, mission mode.
8. **CE + data path**: ath10k core start, WMI ready, scan, then join (the donor's `fw/network` mechanism, then the iOS
   Wi-Fi settings through `redwood_apple80211.c`).

    Register map: Samsung `s2mu106_charger.h` (LineageOS android_kernel_samsung_exynos850).
  - BOOT = Test 102 (4c3188b7…).
  - **Test 104 (BOOT 582068b6…, kernel t104 + Test 102 loader):** the kernel reads CHG_STATUS0/1 over SE4 (FIFO, the
    loader's set-up) in the 5-s gauge poll and reports external power / charging / full from the charger itself
    (input status 3 or 5 = power; STATUS1 bits 1:0 = full). iOS's status bar shows the green charging bolt (99 %).
  - **Test 106 (BOOT 04895816…, kernel t106):** charger type from the S2MU106 MUIC (I2C 0x3e, DEVICE_TYP1 0x47 /
    CHG_TYP 0x4d): wall charger 1800 mA, charging port 1500 mA, PC port 900 mA, written to CTRL1 on change; a
    WD_SUSPEND seen again is cleared. Battery capacity to iOS: RBATCAP 0x0e (learned, mAh<<2: 4180 mAh), BATCAP
    0x10 (as made, mAh). Seen: "on a computer's port (USB): 900 mA".
- Live boot-args (Test 82): every `wifi_*` switch is set with `python phone.py args ...` (kept in USERDATA, applied
  at the next start), so each Wi-Fi step needs no new BOOT image unless code changes.

## Safety

Read-only first at every stage. Writes go only to the modem's own reserved memory and to the SMEM items that the
protocols define. Never to PMIC supply rails, never to the phone's EFS partitions (rmtfs writes stay in RAM). Every
run ends with the modem shut down through TZ, after asking it to stop over SMP2P.
